## 保留的产品设计

- UPLOAD 是用户明确触发的本地优先完整覆盖；没有擅自改成每次都弹 Diff。
- Rows 是最少行数；不会为了满足“固定容量”而隐藏多余书签。
- 搜索仍为简洁单列，LEFT / CENTER / RIGHT 对齐继续有效；HIDE 只隐藏提示。
- Token 明文输入是现有明确设计。新增的是保存选择和风险说明，不改变输入展示方式。
- Online 只读远端；普通启动检查只读，明确保存 Token 时才允许首次创建 Gist。

## 验证与边界

完整 `npm run check` 已通过：30 个测试文件、178 项单元/集成测试、16 项 Chromium E2E，扩展及 Online 构建成功，生产依赖审计 0 漏洞，lint、格式与类型检查全部通过。浏览器测试使用独立临时配置和模拟 GitHub，不访问实际账号，不修改用户真实书签。Notes 截图也已检查，排序控件与内容区无重叠。

这不是“全项目再无问题”的保证：

- Gist 的读取、核对、写入并非原子事务。完整快照方案仍不承诺多个设备严格同时写入时的原子合并；本轮没有用本地锁冒充跨设备锁。
- 当前 E2E 使用安装的 Chromium。最低 Chrome 120、其他浏览器、真实 GPU/驱动组合仍需要发布前兼容性测试；软件渲染测试不能覆盖全部硬件差异。
- GitHub Pages 不支持这里所需的自定义响应头，无法与 Cloudflare/Vercel 达成相同托管策略；已提供应用层嵌入拒绝并明确部署限制。
- 隐私政策公开地址、维护者支持渠道、商店后台披露、截图和正式发布需要维护者实际填写/确认。新增 CI 配置已落盘，尚未在远端 GitHub 执行。
- 本轮不自动提交、打标签、部署或商店发布。源码和测试保持在本地工作区。
