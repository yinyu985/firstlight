Firstlight 使用帮助

Firstlight 扩展直接展示 Chrome 书签栏。连接 GitHub 后，书签、Notes 和显示设置会作为一个完整快照保存在你的 Secret Gist。Online 只读展示这个快照。

连接 GitHub

  1. 打开 GitHub 的 fine-grained personal access token 页面，设置到期时间。账号权限只授予 Gists 读写权限；不要授予仓库、组织或管理权限。如果使用 classic token，只勾选 gist。所有设备和 Online 必须使用同一个 Token 才能解密 Notes，不能另建不同的只读 Token；Online 本身仍只发送读取请求。
  2. 复制 Token，在 Firstlight 设置的 SYNC 中粘贴并保存。不要把 Token 发给他人、放进截图、网址或笔记。
  3. 新连接默认仅保留当前会话。扩展在浏览器重启、扩展重载或更新后需要重新连接；Online 在该标签页会话结束后需要重新连接。只有勾选“Remember token on this device”才会长期保存。旧版本已保存的 Token 会保留原来的长期保存选择；取消勾选后再次保存即可改为会话模式。
  4. 扩展会自动寻找 Firstlight Gist；没有时立即用当前数据创建。存在多个时选择 GitHub 最近更新的一份。Online 不创建任何远端数据。

同步、冲突与恢复

连接建立后，本地连续 10 秒没有修改才自动上传。双方同时变化会打开 Diff，让你选择保留哪一份。USE LOCAL 用本机完整快照覆盖远端；USE REMOTE 用远端完整快照替换本机书签栏、Notes 和同步设置。这不是逐条合并。

UPLOAD 是明确的本机优先覆盖操作。拿不准时先用对比功能。恢复前保留最近三份内部恢复点，用于写入失败或中断时回滚。大快照会显示摘要，并提供本机/远端原文下载；摘要不代表所有差异已经展示。

Notes 压缩、加密与更换 Token

上传时仅 Notes 正文自动 gzip 压缩，再用同一个 Gist Token 通过 HKDF-SHA-256 派生的 AES-256-GCM 密钥加密，不需要第二个密码。笔记标题、ID 和时间保留在 notes.items 中，方便直接在 Gist 检查；书签、设置和顶层时间也为明文。本地笔记和下载的 Diff 原文不加密。

所有设备与 Online 必须使用当前格式；不兼容或自动迁移历史配置与旧明文 Notes。旧格式读取失败不会覆盖本地数据。已有 Gist 历史中的明文不会随新加密功能消失。

同账号更换 Token 请在仍保存旧 Token 的扩展中直接保存新 Token，不要先清空旧值。扩展使用旧 Token 解密远端 Notes，再用新 Token 重加密，验证后才切换；失败或 Worker 重启后暂停同步，再次保存同一个新 Token 可继续。在迁移完成前不能切换其他连接或清空凭证。迁移凭证各自遵循会话/记住选择，会话结束后可能需要重新输入。旧 Token 即使已撤销仍可在本地解密；字符串丢失则无法解开旧密文。其他设备和 Online 随后改用新 Token；历史密文仍需要当时的 Token。

断开与删除数据

清空 Token 输入框，点击 CLEAR，会清除 Firstlight 保存的 Token 并断开连接，不会删除你的 Chrome 书签、Notes 或 GitHub Gist。到 GitHub Token 设置撤销 Token，才能使这份凭证在所有地方失效。远端快照需要你在 GitHub Gist 中主动删除；GitHub 可能保留历史版本，具体由其政策决定。

数据与书签页面

仅有 Gist 链接不能解密新版 Notes，但仍能读取笔记标题、ID、时间、书签、设置和旧明文历史。Token 泄露会同时暴露访问权限和 Notes 解密能力；GitHub 鉴权会收到 Token，因此此方案不对 GitHub 保密。请勿在同步笔记中保存密码、私钥或长期凭证。

打开 data: 书签可能执行该书签自带的脚本并访问它指定的网站。Online 使用隔离来源的启动器打开，书签无法读取 Firstlight 的 Token。javascript:、file:、chrome: 及自定义协议会完整保存在快照中，但 Firstlight 不直接执行或打开。
